1. 진행 방식

엔진 연결과 대화만 되는 템플릿을 받아서, 내 일에 맞는 앱으로 키웁니다. 코드는 직접 짜지 않고 내 코딩 에이전트에게 말로 맡깁니다.

처음 한 바퀴는 수업에서 함께 합니다. 그 뒤로는 각자 필요한 기능을 하나씩 붙입니다. 수업에서 설명한 내용을 이 페이지에서 다시 볼 수 있습니다.

순서하는 일바뀌는 곳
받기내 레포에 들어온 my-agent-platform/ 받기내 레포
분석코딩 에이전트에게 앱의 구조 듣기없음
켜기앱을 켜고 엔진 연결없음
이름과 색내 앱의 이름, 한 줄 소개, 색custom/brand.json, app/static/style.css
기능할 일 목록을 만들고, 써 보고 다듬기app/, tests/
남기기일지, 변경 기록, 커밋, 푸시기록/

이 페이지의 요청문은 kiro-cli 기준입니다. Claude Code나 Codex를 쓰면 같은 요청문을 내 도구에 넣습니다.

요청문의 이름, 색, 할 일은 예입니다. 내 것으로 바꿔서 넣습니다.

필요한 것: Python 3.10 이상, Kiro IDE, Kiro CLI(kiro-cli). 설치할 Python 패키지는 없습니다. 수업 화면은 Kiro IDE 1.4.86, kiro-cli 3.3.0입니다.

앱 켜기 (macOS)

앱 켜기 (Windows)

  1. 브라우저에서 http://127.0.0.1:8765가 열립니다.
  2. 왼쪽 엔진 카드에서 로그인된 엔진의 "연결" 버튼을 누릅니다.

5. 이름과 색 바꾸기

여기부터는 코딩 에이전트(kiro-cli)에 넣습니다.

색을 바꾸는 요청문

색은 app/static/style.css 맨 위의 :root에 모여 있습니다.

kiro-cli는 명령을 실행하기 전에 허락을 묻습니다. 실행할 명령을 읽고 Allow once에서 Enter를 누릅니다. 막으려면 Deny once를 고릅니다. 기능 하나를 만드는 동안 여러 번 묻습니다.

9. 작업한 날마다 남기기

작업한 날에는 끝내기 전에 기록하고, 커밋하고, 푸시합니다. 수업 밖에서 작업한 날에도 똑같이 남깁니다.

10. 막혔을 때

  • git pull이 안 됨 — 2. 템플릿 받기의 "git pull이 막힐 때"를 봅니다.
  • 코딩 에이전트가 앱의 구조를 모름 — 레포 맨 위에서 실행한 경우입니다. 끄고 my-agent-platform 폴더 안에서 다시 실행합니다.
  • python3 명령이 없음 — Windows에서는 python dashboard.py로 실행합니다.
  • 고쳤는데 화면이 그대로임 — 브라우저를 새로 고칩니다. 그래도 그대로면 앱을 Ctrl+C로 끄고 다시 켠 뒤 엔진을 다시 연결합니다.
  • Kiro 엔진에 "연결" 버튼이 없음 — 터미널에서 kiro-cli login으로 로그인합니다.
  • 엔진이 멈춘 것처럼 보임 — 허락 카드가 떠 있는지 봅니다. 5분 안에 누르지 않으면 거절합니다.
  • 푸시가 거부됨(403, permission denied) — 레포 초대를 수락했는지 확인합니다.
  • 테스트가 실패했다고 함 — 코딩 에이전트에게 "실패한 테스트와 까닭을 알려 주고, 고치기 전에 방법을 말해 줘"라고 합니다. 테스트를 지워서 통과시키자는 제안은 받지 않습니다.

요청문의 앱 이름, 색, 할 일은 예입니다. 화면과 답은 사람마다 다르게 나올 수 있습니다. 앱의 구조와 문서는 각자의 레포 my-agent-platform/을 기준으로 합니다.
